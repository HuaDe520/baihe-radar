# 百合雷达 Baihe Radar 🏳️‍🌈

> 输入任意名字（含网名/外国名），用一个小神经网络做「名字雷达」：
> 性别倾向、ACG 属性、ACG 百合角色、角色取向（虚构）、百合指数。
>
> **纯娱乐向玩具。** 训练数据是真实姓名统计 + 虚构角色/小说数据；不能也不应用于判断任何真实个人的性取向或性别身份。

**在线体验**：<https://huade520.github.io/baihe-radar/> ｜ **仓库**：<https://github.com/HuaDe520/baihe-radar>

![百合雷达预览](docs/preview.png)

## 它输出什么（v4 五头）

| 输出 | 数据 | 说明 |
| --- | --- | --- |
| **性别倾向** 女/男 | 真实姓名语料 8 万条（中文 4 万 + 外国名/音译 4 万） | 「名字用字像女名/男名」，统计倾向，不是身份判断 |
| **ACG 属性** 伪娘/扶她/伪郎/普通 | 萌娘百科角色分类 1,054 条 | 只对二次元角色名有参考价值 |
| **ACG 百合角色** 其他角色/百合角色 | 萌娘百科「分类:百合」角色 177 条 vs 普通角色 519 条 | 虚构角色标签，非真人 |
| **角色取向（虚构）** 百合/纯爱(BL)/直向 | 晋江作品频道主角名 18,113 条 | 用小说频道标签当虚构角色取向的代理 |
| **百合指数** | 同上（二分类头） | 页面大圆环 |

支持**中英文混输 + 网名**：`林晚`、`Alice`、`林晚_233`、`xX_张伟_Xx` 都能跑（训练时对数字/下划线后缀做了增广）。
逐字贡献可切换查看对「百合指数 / 性别 / ACG 属性 / 百合角色」的贡献。

## 数据从哪来

- **真实姓名（性别）**：[Chinese-Names-Corpus](https://github.com/wainshine/Chinese-Names-Corpus) 的中文姓名性别语料（120 万，抽 4 万）+ 外国名语料（46 万，抽 4 万，含中文音译与拉丁原名）
- **ACG 性别表达 / 百合角色**：萌娘百科公开分类页（伪娘 / 扶她 / 伪郎 / 女装 / 男装 / 分类:百合 / 按生日分类负样本），抓取脚本 `data/scrape_moegirl.py`
- **作品频道 / 百合判定**：晋江文学城作品库三个频道（`xx0=3/2/1`）公开「主角名」字段，11,742 本书 → 18,113 个去重主角名（见 `data/DATA_REPORT.md`）
- **网名增广**：训练时给部分样本加 `_233 / 666 / _01 / xX_…` 等后缀，让模型对网名鲁棒

## 模型（v4 五头）

```
字 embedding 32 + 位置 embedding 8（拼接 40 维/位置，max_len=12）
  → 三路卷积 k=1/2/3（64/96/96 通道）+ BatchNorm → ReLU
  → 每路 max-pool + mean-pool（512 维）→ 拼首字/末字 embedding（576）
  → FC 160 → ReLU → 5 个分类头
参数量约 27 万，权重导出 web/model.json（约 1.7 MB），浏览器端 JS 前向推理
（与 numpy 参考实现 5 头误差 < 1e-6，232 条对拍通过）
```

| 指标 | 数值 |
| --- | --- |
| 性别 · 中文名 | **97.3%**（4,000 条测试） |
| 性别 · 外国名/音译 | **88.0%** |
| ACG 属性（4 类） | acc **61.2%** / 平衡 61.3%（103 条测试，数据仍偏少） |
| ACG 百合角色（2 类） | acc **82.4%** / 平衡 **68.6%**（68 条测试） |
| 角色取向（3 类） | acc 46.8%（多数类基线 33.5%） |
| 百合指数平衡准确率 | 55.0% |

## 为什么不做「真实公众人物的性取向概率」？

性取向/性别认同属于敏感个人信息；「公开出柜」只代表本人选择公开，**不能反推没公开的人是异性恋**，
拿「公开 vs 未公开」训练出来的模型学到的其实是名人/网名风格，不是取向，指标再高也是假的。
这类工具还容易被用来给真人贴标签、逼人出柜。所以本项目只做：
**真实姓名的性别统计**（匿名语料，97.3%/88.0%）、**虚构角色/小说的取向代理**（不指向真人）。
区别：性别是「名字用字的统计规律」，取向是「虚构作品的频道标签」，都不是对真人的判断。

## 取向套娃（虚构/娱乐，v5）

受 [B 站《更多性取向》](https://www.bilibili.com/video/BV1KauJ6xEPT/) 启发，把「取向」看成**递归关系**而不是单标签：
`取向 = (自己性别, 喜欢的对象的类型)`，而「喜欢的对象的类型」自己也可以有取向，于是可以套娃 N 层（视频里叫「爱的 N 次方」）。

页面实现（纯前端规则组合器 `web/orientation.js`，不训练、不预测真人）：

- **L0 四类**：直男 / 直女 / 男同 / 女同，由性别头（真实姓名统计）与作品频道头（虚构标签）组合推导；
- **L1~L3**：按手写转移先验递归展开，展示 top5 链，例如 `女同 → 喜欢 直女 → 喜欢 男同`；
- 概率 = L0 × 每层转移概率，top5 归一化；可切 1/2/3 层、可「🎲 换一个」。

⚠️ 套娃链是**捏造的娱乐规则**，不是模型预测，更不是对任何真人的取向判断。

## 和同类玩具的区别

参考过 [Akanyi/Gaynum](https://github.com/Akanyi/Gaynum)：纯前端**确定性哈希**，README 自认「结果纯随机，没有任何依据」，没有数据集也没有准确率。
本项目真的训练了 5 个头（真实姓名 + 萌娘百科 + 晋江），所以有这些诚实（也不算高）的数字。

## 本地运行

```bash
# 1. 姓名语料（仓库外）
git clone --depth 1 https://github.com/wainshine/Chinese-Names-Corpus.git D:\names-corpus

# 2. 可选：重抓 ACG 角色分类（已有 data/moe_*.jsonl 可跳过）
python data/scrape_moegirl.py

# 3. 训练 v4 + 导出
python train/train_v4.py --corpus-root D:\names-corpus --out web/model.json

# 4. 对拍 + 预览
python train/make_vectors_v4.py web/model.json
node web/parity_test.mjs
python -m http.server 8000 -d web
```
